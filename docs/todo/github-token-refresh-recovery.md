# GitHub token 갱신 복구 개선

상태: 후속 검토. 외부 원자성의 한계 기록.
관련: [PLAN-0017 연결과 권한](../plans/PLAN-0017-github-app-issue-task-integration.md#연결과-권한)

## 현재 범위와 한계

현재 PLAN은 계정별 갱신 claim, token version, 중복 갱신 억제와 재인증 복구를 포함한다.
GitHub에서 refresh token을 소비한 뒤 응답 유실 또는 DB 저장 전 종료가 발생할 수 있다.
원격 token 회전과 로컬 저장을 하나의 transaction으로 만드는 것은 보장 대상이 아니다.

## 후속 작업

- [ ] 실제 실패 빈도와 재인증 발생 원인을 비밀 없이 계측한다.
- [ ] 응답 수신부터 안전한 저장까지의 구간과 장애 복구 절차를 개선한다.
- [ ] 공식 API가 복구·재시도 보장을 제공하는지 재검토하되 근거 없는 재시도는 추가하지 않는다.
- [ ] 불가피한 재인증 시 기존 연결을 보존하고 사용자가 복귀할 수 있는 안내를 개선한다.

## 검증 기준

동시 갱신, 응답 유실, 저장 실패, 작업자 종료 후 재시도를 검증한다.
유효한 새 token을 구 token 실패 때문에 폐기하지 않고, 복구 불가 상태는 명시적으로 재인증으로 전환한다.
token 로그 출력이나 소비된 refresh token의 무한 재시도는 허용하지 않는다.
기본 실패 처리 검증은 현재 PLAN에서 완료해야 한다.
