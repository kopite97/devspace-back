# GitHub 접근 철회 지연 개선

상태: 후속 검토. 연동 구현·측정 전이며 착수 승인 아님.
관련: [PLAN-0017 연결과 권한](../plans/PLAN-0017-github-app-issue-task-integration.md#연결과-권한)

## 현재 범위와 한계

현재 PLAN은 접근 검증 유효기간, 철회 이벤트에 의한 무효화, 재검증 실패 시 차단을 구현한다.
GitHub와 로컬 DB 사이의 원자적 권한 확인이나 철회 순간의 무지연 차단은 보장하지 않는다.
이미 브라우저에 전달한 내용과 적법하게 일반 Task로 전환한 사본은 원격 회수할 수 없다.

## 후속 작업

- [ ] 실제 호출량과 철회 인지 지연을 측정하고 사용자/저장소별 검증 주기를 개선한다.
- [ ] 조직 구성원·팀·SSO 변경에서 감지 가능한 이벤트와 재조회가 필요한 경로를 확인한다.
- [ ] 필요한 경우 화면 접근 시 추가 재검증의 비용과 효과를 비교한다.
- [ ] 프론트엔드에 공개할 관측 지연과 확인 대기 상태를 측정 결과에 맞춰 갱신한다.

## 검증 기준

철회·token 만료·외부 장애 시나리오에서 검증 만료 후 private 내용이 노출되지 않아야 한다.
목록·검색·집계·재실행의 접근 조건이 일치하고, 동시 요청이 과도한 API 호출을 만들지 않아야 한다.
지연 개선을 무지연 보장으로 표현하지 않는다. 기본 차단 정책은 현재 PLAN의 필수 항목이다.
