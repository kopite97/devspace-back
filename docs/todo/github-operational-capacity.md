# GitHub 연동 운영 용량 조정

상태: 보수적 기준값과 격리된 경계 검증 완료. 실제 규모의 운영 측정은 후속 필요.
관련: [PLAN-0017 동기화와 API 경계](../plans/PLAN-0017-github-app-issue-task-integration.md#동기화와-api-경계)

## 현재 PLAN 필수 작업

- [x] 권한 검증 유효기간·시간 제한, 해제 batch 크기, 수집/보관/응답 상한, 복구 주기를 고정했다.
- [x] 51개 원본의 50개 단위 해제·부분 중단, 동시 수동/자동 가져오기, 페이지/total,
  외부 확인 중 transaction 부재를 격리 검증했다. 운영 최대 규모 부하 시험은 아니다.
- [x] rate limit·HTTP 크기/시간 제한·자격증명 gate·재시도 상한을 검증했다.
  선택 가져오기 대기열은 연결당 10개로 제한하고 초기 baseline 완료 전 자동 가져오기를 막는다.

수치·범위는 [구현 검증 기록](../reviews/plan0017/implementation-validation.md)에 있다.
영속 원본 수집 이력/작업의 전체 저장 공간이나 무한한 외부 이벤트 입력을 일정 용량으로
제한한다는 보장은 하지 않는다. 실제 backlog 보관 정책과 공정성은 아래 후속 측정 대상이다.

## 후속 운영 작업

- [ ] 실제 저장소/Issue 규모와 활성 사용자 수를 바탕으로 기준값을 조정한다.
- [ ] 권한 확인 트래픽과 동기화 트래픽을 구분하고 설치/사용자별 병목을 확인한다.
- [ ] 공정한 작업 분배, 장기 실패 작업 정리와 관측 지표의 보관 비용을 개선한다.

## 검증 기준

측정한 환경·데이터 규모·설정값과 결과를 함께 기록한다. 근거 없이 최적값을 주장하지 않는다.
후속 운영 튜닝을 이유로 현재 PLAN의 상한 설정과 격리 검증을 미루지 않는다.
새 인프라·의존성 도입은 자동 후속 조치가 아니며 필요성과 승인을 별도로 확인한다.
